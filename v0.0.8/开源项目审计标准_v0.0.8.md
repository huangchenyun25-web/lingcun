# 另存人生 · 开源项目审计标准（v0.0.8 说明）

> **v0.0.8：规则不变。** 红线 R1–R9、10 项打分、判定、实测 T1–T5、维护、第五节统计，全部沿用《开源项目审计标准_v0.0.7》，这里不重抄。本页只写四处跟 v0.0.8 页面有关的说明（2026-10-23，依据《实时反馈_待改》第 70、72、78、85 条）。

1. **R2「要 API 密钥、要接模型」只管开源起点项目和用户做出来的东西，不管另存人生页面自己的 AI 入口层。**
   v0.0.8 页面可以让用户填自己的 API 密钥、由浏览器直接调模型（第 85 条），这是另存人生的设置，不是拿来给用户当起点的开源项目，不按本标准打分。用户做出来的第一件东西仍然不能要 API 密钥、不能接模型（引导协议原则 11）。

2. **页面里 AI 做出来的小网页，用同一组红线做机械检查。**
   页面对每一版 `index.html` 自动核对：完整文件、不引用外部文件（对应 R4、R6）、不联网（R4）、数据存在本机、不用填密钥（R2）、界面中文。有不过的项，提示用户「改一处」去掉。这不是审计，不能让做出来的东西「进库」；进库仍要按 v0.0.7 第四节真跑 T1–T5。

3. **适用范围的一句话更新**：第一件东西「想公开时发布成 GitHub Pages」改为「想公开时自己选公开方式，做成网页的推荐 GitHub Pages」（第 72 条）。R6 里「参考《发布可达性》」照旧适用于选 GitHub Pages 的情况。

4. **复盘案例不涉及开源起点项目**，不走本标准。它的「不编造」由引导协议「复盘案例」一节和页面的数字核对管。

待拍板时再改：如果以后接入我们自己的 API 和后端（第 70 条），要另写一条「页面自身的数据外发」规则（发到哪、存多久、谁能看），放在引导协议里，不放在本标准里。
