# 另存人生 · 开源项目审计标准（v0.0.7）

> **v0.0.7 改动（2026-10-23，依据《实时反馈_待改》第 48、49、63–67 条）**
> - **「不带统计代码」红线放宽**（第 49 条）：开源项目**本身**仍不能带统计（R4、第 8 项不变）；但用户做完项目后**主动问起访问量**时，允许用户自愿在自己的页面里加**一种**免注册的静态计数器（不蒜子 busuanzi）。不推荐任何要注册、绑定域名或备案的商业统计。见新增第五节。
> - **适用范围**跟着引导协议 v0.0.7 改成「第一件东西」：一个只做一件事的小网页（默认单文件 `index.html`），公开不再是做成的前提；补证据项目才必须公开。
> - **兜底入口**（「我暂时没想法，给我一个今天就能开始的小项目」）只允许用「进库」且 T1–T5 全部通过的卡（第 63 条；三方审阅·ChatGPT「预先测试过的模板」）。
> - 第四节 T4 补一句：审计时看的是卡本身；用户事后自愿加的计数器不算卡的问题。第六节（原第五节）引导者用法同步。
> - 其余（红线 R1–R9、10 项打分、判定、实测 T1–T5、维护）与 v0.0.6 相同。
>
> 用途：判断一个 GitHub 开源项目，能不能拿来当零基础或初用者「第一件东西」的起点。
> 适用范围：先只管「第一件东西」这个场景（一个只做一件事的小网页；想公开时发布成 GitHub Pages 公开链接）。其他路线（大健康、出海等）以后另加。
> 这份标准替代《产品与竞品分析》4.4 的 16 分表，在这个场景下使用。4.1 的原则不变：**没真跑过的，最多标"待验证"，不进库。**

## 一、红线（任一条命中，直接不收，不打分）

| # | 红线 | 怎么查 |
|---|---|---|
| R1 | 没有许可证，或许可证不允许商用、不允许修改 | 仓库根目录的 LICENSE 文件；GitHub 页面右侧的 License 标识。显示 "Other / NOASSERTION" 的，要打开文件看清楚，看不清就不收 |
| R2 | 要 API 密钥、要接模型、要自己搭模型 | README 和代码里搜 `API_KEY`、`OPENAI`、`token`、`.env` |
| R3 | 要服务器、数据库、Docker 才能用核心功能 | README 的安装步骤；有没有后端代码是必需的 |
| R4 | 会把用户输入的内容发到第三方，或有去不掉的追踪（项目**自带**的统计按这条和第 8 项判；用户事后自愿加的计数器见第五节） | 用浏览器打开，看网络请求发到了哪些域名（见第四节"实测"）；代码里搜 `fetch(`、`analytics`、`gtag` |
| R5 | 核心代码被压缩或混淆、看不出在做什么 | 打开主要的 .js 文件，是不是一整行乱码 |
| R6 | 核心功能依赖国内打不开的服务 | 例如只能部署在 Vercel、只能调用国内打不开的接口。参考《发布可达性_v0.0.6》 |
| R7 | 内容碰黑名单 | 卖课、卖资料、代写、刷单、灰色工具、收款、诊断和用药、他人隐私或公司内部资料、私域引流（微信号、二维码、群） |
| R8 | 仓库已归档（Archived）**并且**有未修的安全问题 | GitHub 页面顶部的黄色归档提示；Issues 里搜 security |
| R9 | 审核人没有真跑过 | 没按第四节跑通的，只能标"待验证"，不进库 |

## 二、打分表（10 项，每项 0 / 1 / 2，满分 20）

| # | 项 | 2 分 | 1 分 | 0 分 |
|---|---|---|---|---|
| 1 | **合用户的需要** | 正好是用户"最近想解决的问题"要的那个小东西 | 要删掉一些功能才合用 | 只是看起来相关 |
| 2 | **许可证** | MIT、Apache-2.0、BSD 等宽松许可 | GPL 等要求"改了也得开源"的（公开仓库可以接受，但要告诉用户） | —（没有许可证已在红线拦下） |
| 3 | **维护** | 180 天内有人工提交（机器人自动升级依赖不算） | 2 年内有提交，或近期只有机器人提交 | 超过 2 年没人动 |
| 4 | **社区健康** | 100 星以上，未关闭的 issue 不多，没有长期没人理的严重问题 | 星少（个人小项目）但代码干净、能跑；或 issue 偏多 | 大量没人理的 bug，或明显刷星 |
| 5 | **不用额外设置** | 不要密钥、不要注册新服务、不要装软件，下载就能看 | 只要一个免费账号（如 GitHub 本身） | —（要密钥、要模型已在红线拦下） |
| 6 | **怎么跑起来** | 纯静态网页：双击 `index.html` 或放上 Pages 就能用；或 GitHub Pages 会自动构建（如 Jekyll） | 要跑一条构建命令（如 `npm run build`）或要改配置才能放上 Pages | 要多步安装、配环境 |
| 7 | **国内网络** | 运行时不依赖外部域名；或依赖的域名在国内测量点打得开 | 依赖境外字体或图标库，打不开时页面还能用但会变慢或变丑 | 核心功能要连国内打不开的服务（已在 R6 拦下） |
| 8 | **安全与数据** | 数据只存在用户自己的浏览器（如 localStorage）或不存数据；不发任何统计 | 有统计代码或外链，但删一行就干净 | 会把用户输入发出去（已在 R4 拦下） |
| 9 | **体量和好不好懂** | 文件少（大约 30 个以内），主要逻辑一两个文件、几百行，让 AI 读一遍就能讲清 | 文件多但结构清楚，用户只需要碰其中一两个文件 | 几百上千个文件，或要懂框架才知道改哪 |
| 10 | **新手能在 AI 帮助下改** | 改标题、颜色、文字、一条链接，只动一个文件，改完刷新就看到 | 要改配置文件或重新构建才看到 | 改一处要动很多地方 |

## 三、怎么判

| 结果 | 条件 | 用户看到什么 |
|---|---|---|
| **进库（零基础默认可推荐）** | 没碰红线；总分 ≥ 16；第 5、6、8 项都是 2 分；第四节 T1–T4 全部通过（T5 没做的标"发布未实测"，在第一次用户测试前补上） | 可以当主推卡 |
| **只给会一点的人** | 没碰红线；12–15 分，或第 6 项是 1 分。T1 没通过的，只有在改一处配置就能修好、并写在卡上时才允许 | 不出现在零基础路径；用户自己说"想挑战一下"时才给 |
| **不收** | 碰任一红线；或低于 12 分；或第 8 项为 0；或实测没通过、又不是改一处配置能修好的 | 不给用户看；在卡片里写下原因 |

另外三条：
- **每张卡必须写"不适合谁"**，没写的不算审完。
- **星数不等于维护**，也不等于安全。星多但两年没动的，维护照样 0 分。
- **一个只做一件事的小网页，"让 AI 从零写"常常比改一个大仓库更简单。** 仓库体量（第 9 项）低于 1 分时，优先建议从零写，把仓库当参考。

## 四、实测步骤（审核人必须做，每张卡记结果）

| 步 | 做什么 | 通过的标准 |
|---|---|---|
| T1 打开 | 下载仓库，用本地静态服务打开，**并且放在子路径下打开**（模拟 `用户名.github.io/项目名/`） | 页面正常显示，样式没丢，没有 404 |
| T2 核心功能 | 按一次它的主功能（加一条任务、开始计时、打开链接） | 功能正常；要存数据的，刷新后还在 |
| T3 改一处 | 像新手那样改一个看得见的地方（名字、标题），刷新 | 改动出现，没有别的东西坏掉 |
| T4 外部请求 | 看浏览器的网络请求发到了哪些域名 | 没有统计、没有把输入发出去；外部字体或图标单独记下。审的是卡本身；用户事后按第五节自愿加的计数器不算卡的问题 |
| T5 发布 | 放到 GitHub Pages（或备选平台）拿到公开链接 | 链接能打开。**没做这一步的，卡片上写"发布：未实测"** |

审核人用 AI 帮忙读 README、许可证、提交记录是可以的，但 AI 的结论不算审过。

## 五、统计：用户问起时才给（v0.0.7 放宽）

原来的口径是「不带统计代码」。v0.0.7 起分成两件事：

| 情况 | 怎么判 |
|---|---|
| 开源项目或精选库卡**自带**统计、追踪（如 googletagmanager、百度统计） | 不变：按 R4 和第 8 项判；进库版本必须去掉 |
| 引导者 / 页面生成的默认项目 | 不加任何统计代码 |
| 用户做完项目后**主动问**「怎么知道有多少人看」 | 允许，按下面的顺序给 |

用户问起时的顺序：
1. 先说**不用加代码**的数据：GitHub 仓库自带的访问数据（Insights → Traffic，只有仓库主人看得到）、Star；发在社交平台的，平台自带的浏览和互动数。
2. 还想在页面上显示访问数，**只推荐一种：不蒜子（busuanzi）**——免注册，在 `index.html` 里加两行代码就能显示访问次数。
3. 同时说清三件事：它会让访客的浏览器连到第三方计数服务（匿名计数也不等于完全没有隐私风险）；网络不好时可能加载慢，但不影响页面本身；不想要了删掉那两行就干净了。
4. **不推荐**任何要注册账号、绑定域名或备案的商业统计（如 Google Analytics、百度统计），也不让 AI 自由发挥推荐别的统计工具。
5. 不主动提统计，不把「加统计」当成做成或证据的前提。证据的真实数据可以只是 L1「自己真用了 3 次」（见《引导协议_v0.0.7》「成果与证据」）。

## 六、在对话里怎么用（给引导者）

1. 先查《精选库_首批卡片_v0.0.6》，有合适的卡，最多给 **1 张主推 + 1 张备选**。用户看到的是"它能帮你做什么、你会得到什么"，不是仓库名和星数。
2. 库里没有合适的，可以去 GitHub 搜。搜到的项目先过一遍红线，再说清楚：**"这是我刚找到的，还没被人工审过（待验证）"**，让用户自己选要不要用。
3. 都不合适，就**直接在用户已有的 AI 里从零写一个**。没匹配到也是合格结果。v0.0.7 页面生成的说明默认就是「从零写单文件 `index.html`」，精选库卡只当样子参考。
4. **兜底入口**（用户说「暂时没想法」）只用「进库」且 T1–T5 全部通过的卡；T5 没过的不进兜底列表。现为卡 1 本周行动清单、卡 2 习惯打卡、卡 3 番茄钟。
5. 不编项目名和链接。搜不了就直说搜不了。

## 八、维护

- 一个人维护就够。每 30–60 天重查一次维护和许可证；任何一张卡在用户测试里失败，立刻重审。
- 撤下的卡不删，留下撤下原因。
- 不按星数、热帖自动收录。
